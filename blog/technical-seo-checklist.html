سئو فنی

چک‌لیست کامل سئو فنی در ۲۰۲۵

۱۵ آذر ۱۴۰۳ • ۸ دقیقه مطالعه • تیم سئو تور

سئو فنی (Technical SEO) زیربنای تمام موفقیت‌های سئو است. حتی اگر بهترین محتوا را تولید کنید و قوی‌ترین بک‌لینک‌ها را بسازید، بدون زیرساخت فنی درست، موتورهای جستجو نمی‌توانند سایت شما را به‌درستی خزش، ایندکس و رتبه‌بندی کنند. در سال ۲۰۲۵ با توجه به تغییرات الگوریتم‌های گوگل، رشد هوش مصنوعی و اهمیت روزافزون تجربه کاربری، سئو فنی از همیشه پیچیده‌تر و در عین حال حیاتی‌تر شده است. این چک‌لیست جامع، تمام مواردی که باید در وب‌سایت خود بررسی و بهینه کنید را در ده بخش کاربردی پوشش می‌دهد.

سئو فنی فقط برای مهندسان نیست؛ هر بازاریاب و صاحب کسب‌وکاری باید بداند سایتش از نظر فنی چقدر سالم است. این مقاله را به‌عنوان مرجع خود نگه دارید و هر سه ماه یک‌بار آن را مرور کنید.

۱. سرعت سایت و Core Web Vitals

سرعت بارگذاری یکی از مهم‌ترین فاکتورهای رتبه‌بندی گوگل است. طبق تحقیقات Google، احتمال پرش کاربران از صفحه‌ای که در ۳ ثانیه بارگذاری نمی‌شود، ۳۲ درصد افزایش می‌یابد و در ۵ ثانیه به ۹۰ درصد می‌رسد. Core Web Vitals مجموعه‌ای از سه معیار کلیدی است که گوگل برای سنجش تجربه کاربری واقعی کاربران استفاده می‌کند. در سال ۲۰۲۵ این معیارها شامل LCP، CLS و INP هستند (FID با INP جایگزین شده است).

معیارهای Core Web Vitals در ۲۰۲۵

  • LCP (Largest Contentful Paint): باید زیر ۲٫۵ ثانیه باشد. این معیار زمان بارگذاری بزرگ‌ترین عنصر قابل مشاهده در viewport را می‌سنجد.
  • INP (Interaction to Next Paint): باید زیر ۲۰۰ میلی‌ثانیه باشد. این معیار جایگزین FID شده و واکنش سایت به تعامل کاربر را در کل صفحه می‌سنجد.
  • CLS (Cumulative Layout Shift): باید زیر ۰٫۱ باشد. این معیار پایداری بصری صفحه و جابجایی ناگهانی عناصر را اندازه می‌گیرد.

برای اندازه‌گیری این معیارها از ابزارهای PageSpeed Insights، Lighthouse، Search Console (بخش Core Web Vitals) و Chrome UX Report استفاده کنید. ابزار WebPageTest نیز برای تحلیل عمیق waterfall بارگذاری بسیار مفید است. هدف باید رسیدن به نمره ۹۰+ در Lighthouse و سبز شدن Core Web Vitals در Search Console باشد.

بهترین روش‌های بهبود سرعت شامل استفاده از CDN مانند Cloudflare یا ArvanCloud، فعال‌سازی HTTP/2 و HTTP/3، فشرده‌سازی تصاویر با فرمت WebP یا AVIF، پیاده‌سازی Lazy Loading، حذف رندرهای مسدودکننده (Render-blocking Resources)، و استفاده از Browser Caching با سیاست‌های مناسب است. در سرور نیز باید از Gzip یا Brotli برای فشرده‌سازی استفاده کنید و PHP نسخه ۸٫۲+ به همراه OPcache فعال داشته باشید.

۲. ساختار سایت و URL

ساختار سایت یکی از پایه‌های سئو فنی است که هم روی خزش موتورهای جستجو و هم روی تجربه کاربر تأثیر مستقیم دارد. یک سایت با ساختار درست، حداکثر ۳ یا ۴ کلیک از صفحه اصلی تا هر صفحه فرعی فاصله دارد. این اصل به «عمق کلیک» (Click Depth) معروف است و گوگل تأیید کرده که صفحاتی که عمیق‌تر از ۴ کلیک هستند، اعتبار کمتری دریافت می‌کنند.

URLها باید کوتاه، توصیفی و شامل کلمه کلیدی باشند. از کاراکترهای خاص، پارامترهای اضافی و IDهای عددی پرهیز کنید. یک URL سئو‌فرندلی به این شکل است: example.com/blog/technical-seo-checklist نه example.com/?p=12345&cat=2. در وردپرس می‌توانید ساختار Permalink را روی Post Name تنظیم کنید تا URLها به‌طور خودکار از عنوان پست ساخته شوند.

برای ساختار سایت ایده‌آل، از مدل «سیلو» (Silo) استفاده کنید. در این مدل، موضوعات اصلی دسته‌بندی می‌شوند و هر دسته دارای صفحات فرعی مرتبط است که با لینک‌های داخلی به یکدیگر متصل می‌شوند. این کار هم PageRank را به‌درستی توزیع می‌کند و هم به گوگل می‌فهماند که سایت شما در یک موضوع خاص مرجع است. از قابلیت Breadcrumbs نیز حتماً استفاده کنید تا هم کاربر و هم ربات مسیر خود را پیدا کنند.

۳. Mobile-First Indexing

از سال ۲۰۱۹ گوگل به‌طور پیش‌فرض از نسخه موبایل سایت‌ها برای ایندکس و رتبه‌بندی استفاده می‌کند. این یعنی اگر سایت شما در موبایل مشکل داشته باشد، حتی نسخه دسکتاپ بی‌نقص هم نمی‌تواند شما را نجات دهد. طبق آمار StatCounter، بیش از ۶۵ درصد ترافیک وب در ایران از موبایل است و این عدد هر سال در حال افزایش است.

سایت شما باید Responsive باشد، نه اینکه نسخه موبایل جداگانه (m.example.com) داشته باشید. Responsive Design با استفاده از Media Queryهای CSS، یک URL و یک محتوا را برای همه دستگاه‌ها ارائه می‌دهد که از نظر سئو بهینه‌ترین حالت است. متن، تصاویر و لینک‌ها باید در موبایل به‌راحتی قابل خواندن و کلیک باشند. اندازه فونت حداقل ۱۶ پیکسل، فاصله بین لینک‌ها حداقل ۴۸ پیکسل و عرض محتوا بدون اسکرول افقی باید باشد.

برای تست نسخه موبایل از ابزار Mobile-Friendly Test گوگل (که اکنون در Search Console ادغام شده) استفاده کنید. همچنین ابزار Chrome DevTools با قابلیت Device Mode به شما کمک می‌کند سایت را در ابعاد مختلف شبیه‌سازی کنید. فراموش نکنید که داده‌های Structured Data، Meta Tagها و محتوای اصلی باید در نسخه موبایل کاملاً یکسان با نسخه دسکتاپ باشند.

۴. Schema Markup و Structured Data

Schema Markup زبانی است که با آن به موتورهای جستجو می‌گویید محتوای صفحه شما دقیقاً درباره چیست. این کار با استفاده از واژگان Schema.org و قالب‌های JSON-LD، Microdata یا RDFa انجام می‌شود. گوگل قالب JSON-LD را ترجیح می‌دهد زیرا جدا از محتوای صفحه قرار می‌گیرد و خواندن آن برای ربات‌ها آسان‌تر است. Schema Markup می‌تواند منجر به Rich Result شود که نرخ کلیک (CTR) را تا ۳۰ درصد افزایش می‌دهد.

انواع مهم Schema برای ۲۰۲۵

  • Article و BlogPosting: برای مقالات و پست‌های بلاگ
  • Organization: برای معرفی کسب‌وکار و لوگو
  • BreadcrumbList: برای مسیر导航 سایت
  • FAQPage: برای صفحات پرسش و پاسخ
  • HowTo: برای راهنمای گام‌به‌گام
  • Product و Review: برای فروشگاه‌های اینترنتی
  • LocalBusiness: برای کسب‌وکارهای محلی
  • Person: برای صفحات نویسندگان (E-E-A-T)

پس از اضافه کردن Schema، حتماً آن را با Rich Results Test گوگل اعتبارسنجی کنید و در Search Console بخش Enhancementها را برای خطاهای احتمالی پایش کنید. در سال ۲۰۲۵ گوگل با معرفی راهکارهایی مانند AboutThisResult و تمرکز بیشتر روی E-E-A-T، اهمیت Schema را دوچندان کرده است.

۵. robots.txt و sitemap.xml

robots.txt اولین فایلی است که ربات‌های جستجوگر در سایت شما می‌خوانند. این فایل در ریشه دامنه (example.com/robots.txt) قرار دارد و به ربات‌ها می‌گوید کدام صفحات را نباید خزش کنند. اما توجه داشته باشید که robots.txt فقط دستور خزش را کنترل می‌کند، نه ایندکس را. اگر می‌خواهید صفحهای ایندکس نشود، باید از متا تگ noindex یا HTTP Header استفاده کنید.

یک فایل robots.txt استاندارد باید حداقل شامل مسیر Sitemap باشد:

User-agent: *
Allow: /

Sitemap: https://seotour.ir/sitemap.xml

Sitemap XML فهرستی از تمام صفحات مهم سایت شما به همراه تاریخ آخرین به‌روزرسانی و اولویت آن‌هاست. این فایل به گوگل کمک می‌کند صفحات جدید را سریع‌تر پیدا کند و صفحات به‌روز شده را مجدداً خزش کند. در وردپرس می‌توانید با افزونه Yoast SEO یا Rank Math به‌طور خودکار Sitemap تولید کنید. در سایت‌های بزرگ، Sitemap Index استفاده کنید که شامل چند Sitemap فرعی برای دسته‌بندی‌های مختلف (پست‌ها، محصولات، صفحات، تصاویر) است.

قانون طلایی: هر URL در Sitemap باید باCanonical URL آن صفحه یکسان باشد. اگر Sitemap شامل URLهای متفاوت باشد، گوگل اعتبار Sitemap شما را کاهش می‌دهد.

۶. Canonical و Duplicate Content

محتوای تکراری یکی از بزرگترین مشکلات سئو است که می‌تواند کل سایت را تحت تأثیر قرار دهد. وقتی گوگل چند صفحه با محتوای یکسان پیدا می‌کند، نمی‌داند کدام را رتبه دهد و معمولاً هیچ‌کدام را رتبه خوبی نمی‌دهد. Canonical Tag به گوگل می‌گوید «از بین این صفحات مشابه، این صفحه نسخه اصلی است و رتبه را به آن بدهید».

Canonical Tag باید در بخش head صفحه به این شکل قرار گیرد:

<link rel="canonical" href="https://seotour.ir/blog/technical-seo-checklist.html" />

مواردی که حتماً باید Canonical داشته باشند شامل: نسخه موبایل و دسکتاپ یک صفحه، نسخه HTTP و HTTPS، نسخه با و بدون www، صفحات پاگینیشن، صفحات فیلتر شده در فروشگاه، نسخه‌های چاپ (print) و URLهای با پارامترهای UTM هستند. همچنین از Canonical برای صفحات هم‌خانواده (Cross-Domain) استفاده می‌کنید زمانی که محتوایی را از سایت دیگری با اجازه بازنشر می‌کنید.

برای بررسی محتوای تکراری از ابزارهای Siteliner، Copyscape و بخش Duplicate Data در Search Console استفاده کنید. هدف باید این باشد که هیچ دو صفحه‌ای در سایت شما بیش از ۸۵ درصد محتوای یکسان نداشته باشند.

۷. خطاهای Google Search Console

Google Search Console مهم‌ترین ابزار رایگان سئو است که گوگل در اختیار شما قرار می‌دهد. این ابزار اطلاعاتی درباره ایندکس شدن، خطاهای خزش، Core Web Vitals، Structured Data، بک‌لینک‌ها و ده‌ها مورد دیگر ارائه می‌دهد. بررسی هفتگی GSC باید بخشی از روتین سئو شما باشد.

بخش‌های کلیدی GSC برای سئو فنی

  • Pages: وضعیت ایندکس همه صفحات (Indexed, Not Indexed, Crawled but not indexed و...)
  • URL Inspection: بررسی وضعیت یک URL خاص، ایندکس بودن، آخرین خزش و خطاها
  • Core Web Vitals: گزارش تجربه کاربری واقعی کاربران
  • Enhancements: بررسی سلامت Structured Dataها
  • Sitemaps: وضعیت Sitemapهای ارسال شده
  • Crawl Stats: آمار خزش گوگل‌بات از سایت شما
  • Security & Manual Actions: جریمه‌های دستی و مشکلات امنیتی

هنگام مواجهه با خطاهای ایندکس، ابتدا دلیل را پیدا کنید. خطای «Crawled - currently not indexed» معمولاً نشان‌دهنده ضعف اعتبار سایت یا کیفیت پایین محتواست. خطای «Discovered - currently not indexed» یعنی گوگل URL را می‌شناسد اما منابع کافی برای خزش آن ندارد. در هر دو حالت باید کیفیت محتوا و پروفایل بک‌لینک را بهبود دهید و از لینک‌سازی داخلی استراتژیک استفاده کنید.

۸. HTTPS و امنیت

از سال ۲۰۱۴ HTTPS یک فاکتور رتبه‌بندی رسمی گوگل است و از سال ۲۰۱۸ مرورگر Chrome سایتی که HTTP است را به‌عنوان «غیرامن» نشان می‌دهد. این هشدار می‌تواند نرخ پرش کاربران را به‌شدت افزایش دهد و اعتبار برند شما را خدشه‌دار کند. در سال ۲۰۲۵ با توجه به رشد تهدیدات سایبری، امنیت دیگر اختیاری نیست.

برای فعال‌سازی HTTPS باید گواهینامه SSL/TLS از مراجع صادرکننده معتبری مانند Let's Encrypt (رایگان)، DigiCert یا Sectigo دریافت کنید. پس از نصب گواهینامه، باید Redirect 301 از HTTP به HTTPS تنظیم کنید و HSTS (HTTP Strict Transport Security) را فعال کنید تا مرورگرها همیشه از HTTPS استفاده کنند. همچنین HSTS Preload List گوگل را در نظر بگیرید تا سایت شما در لیستpreload مرورگرها قرار گیرد.

برای تست امنیت SSL از ابزار SSL Labs SSL Test استفاده کنید و aim خود را نمره A+ قرار دهید. علاوه بر SSL، موارد امنیتی دیگر مانند تنظیم Security Headers (X-Content-Type-Options، X-Frame-Options، Content-Security-Policy)، جلوگیری از حملات DDoS با WAF و به‌روزرسانی مداوم CMS و افزونه‌ها برای جلوگیری از هک و تزریق کد مخرب ضروری است. سایت‌های هک‌شده می‌توانند به‌سرعت از نتایج جستجو حذف شوند.

۹. JavaScript SEO

با رشد فریم‌ورک‌های مدرن مانند React، Vue و Angular، JavaScript SEO به یکی از چالش‌های اصلی سئو فنی تبدیل شده است. مشکل اینجاست که ربات‌های جستجوگر JavaScript را به‌تأخیر اجرا می‌کنند و در نتیجه، محتوایی که با JS رندر می‌شود ممکن است دیرتر یا اصلاً ایندکس نشود. طبق تحقیقات، گوگل می‌تواند ۹۵ درصد JavaScript را رندر کند، اما این کار منابع زیادی می‌برد و ممکن است تا چند روز طول بکشد.

برای اطمینان از اینکه محتوای JS شما به‌درستی ایندکس می‌شود، از ابزار URL Inspection در Search Console استفاده کنید و روی «Test Live URL» و سپس «View Tested Page» کلیک کنید. در تب «More Info» می‌توانید ببینید چه HTML و چه کد JS اجرا شده است. همچنین ابزار Mobile-Friendly Test و Rich Results Test خروجی رندر شده را نشان می‌دهند.

بهترین روش‌ها برای JavaScript SEO شامل: استفاده از Server-Side Rendering (SSR) یا Static Site Generation (SSG) به‌جای Client-Side Rendering (CSR)، تأخیر در بارگذاری اسکریپت‌های غیرضروری، استفاده از defer یا async، و قرار دادن محتوای مهم در HTML اولیه است. اگر از Next.js یا Nuxt.js استفاده می‌کنید، قابلیت SSR به‌طور پیش‌فرض فعال است. برای وردپرس، اگر از page builderهای مبتنی بر JS استفاده می‌کنید، حتماً کش صفحه را فعال کنید.

۱۰. ایندکس شدن و خزش

ایندکس شدن اولین گام برای رتبه‌بندی است. اگر صفحه‌ای ایندکس نشود، هرگز در نتایج جستجو ظاهر نمی‌شود. برای مدیریت ایندکس از دو ابزار استفاده می‌کنیم: متاتگ Robots و HTTP Header X-Robots-Tag. متاتگ noindex به گوگل می‌گوید این صفحه را ایندکس نکن، اما هنوز می‌توانی آن را بخزشی تا لینک‌ها را دنبال کند.

صفحاتی که باید noindex داشته باشند شامل: صفحات تگ، صفحات جستجوی داخلی، صفحات پاگینیشن (در برخی موارد)، صفحات نویسندگان در سایت‌های تک‌نویسنده، نسخه‌های چاپ، صفحات تشکر پس از فرم، صفحات ورود و ثبت‌نام و صفحات فیلتر فروشگاه است. هرگز noindex و nofollow را با هم استفاده نکنید، زیرا nofollow باعث می‌شود ربات لینک‌های آن صفحه را دنبال نکند و در نتیجه صفحات داخلی متصل، ایندکس نشوند.

برای تسریع ایندکس صفحات جدید، از «Request Indexing» در URL Inspection استفاده کنید (البته این قابلیت موقتاً محدود شده است). همچنین می‌توانید با اشتراک‌گذاری لینک در شبکه‌های اجتماعی، فعال‌سازی RSS Feed و ارسال Sitemap به‌صورت خودکار، فرآیند کشف را تسریع کنید. اگر سایت شما بزرگ است و هزاران صفحه دارد، از Crawl Budget Optimization استفاده کنید: صفحات کم‌اهمیت را بلاک کنید و اعتبار خزش را به صفحات ارزشمند اختصاص دهید.

نتیجه‌گیری

سئو فنی یک کار یک‌باره نیست، بلکه فرآیندی مستمر است که باید هر فصل مرور شود. ده بخشی که در این چک‌لیست بررسی کردیم، اساسی‌ترین مواردی هستند که هر وب‌سایتی باید روی آن‌ها مسلط باشد. از Core Web Vitals و Mobile-First گرفته تا Schema، Canonical و JavaScript SEO، همه این موارد با هم کار می‌کنند تا سایت شما برای خزش، ایندکس و رتبه‌بندی بهینه شود. اگر این چک‌لیست را به‌درستی پیاده کنید، می‌توانید انتظار بهبود ۲۰ تا ۵۰ درصدی ترافیک ارگانیک را در عرض سه تا شش ماه داشته باشید. فراموش نکنید که سئو فنی بدون محتوای باکیفیت و بک‌لینک معتبر کامل نمی‌شود؛ این سه ستون کنار هم نتیجه می‌دهند.
